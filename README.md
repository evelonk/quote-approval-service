# Quote Approval Service

Сервис согласования коммерческих предложений на Python 3.12, FastAPI и PostgreSQL.

Сейчас менеджер может создать пустой черновик для закрепленной за ним организации и прочитать его по ID. Черновик сохраняется в базе после перезапуска. Аутентификация — HTTP Basic, пароли хранятся в виде хешей Argon2. Другой менеджер не видит чужой черновик; руководитель и клиент не имеют доступа к черновикам.

Позиции каталога, расчет цены, редактирование, версии, согласование, отправка и решения клиента пока не реализованы.

## Запуск

Нужны Git и Docker Desktop с Docker Compose. Docker Desktop должен быть запущен.

Из папки репозитория:

```bash
cp .env.example .env
```

В `.env` замените обе заглушки своими локальными паролями. Для `DEMO_PASSWORD` используйте не менее 12 символов. Файл `.env` исключен из Git.

```bash
docker compose up --build -d --wait
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Если приложение не запустилось, посмотрите логи:

```bash
docker compose logs api db
```

Документация API: http://127.0.0.1:8000/docs. В **Authorize** укажите имя пользователя из таблицы и пароль из `DEMO_PASSWORD`.

При первом запуске создаются таблицы и учебные записи:

| Пользователь | Роль | Доступ |
| --- | --- | --- |
| `manager1` | Менеджер | Организация 1 — Demo Client A |
| `manager2` | Менеджер | Организация 2 — Demo Client B |
| `lead` | Руководитель | Нет доступа к черновикам |
| `client` | Представитель клиента | Нет доступа к черновикам |

Для локальной демонстрации у всех четырех записей один пароль из `DEMO_PASSWORD`. Повторный запуск не удаляет записи и не меняет существующие пароли. Изменение `DEMO_PASSWORD` в `.env` не обновляет пароли в базе.

## Проверка API

Создайте черновик для организации 1. `curl` запросит пароль `manager1`:

```bash
curl -i -u manager1 -H 'Content-Type: application/json' \
  -d '{"client_org_id":1,"comment":"Первый черновик"}' \
  http://127.0.0.1:8000/quotes
```

Ожидается `201 Created`, `status: "draft"` и `owner_id: 1`. Подставьте полученный `id` вместо `<ID>` в следующих командах.

Прочитайте созданный черновик:

```bash
curl -i -u manager1 'http://127.0.0.1:8000/quotes/<ID>'
```

Ожидается `200 OK` с данными созданного черновика.

Проверьте доступ без входа, от другого менеджера и от руководителя:

```bash
curl -i 'http://127.0.0.1:8000/quotes/<ID>'
curl -i -u manager2 'http://127.0.0.1:8000/quotes/<ID>'
curl -i -u lead 'http://127.0.0.1:8000/quotes/<ID>'
```

Ожидаются соответственно `401`, `404`, `403`. Данные черновика в этих ответах отсутствуют.

Проверьте сохранение данных после перезапуска:

```bash
docker compose down
docker compose up -d --wait
curl -i -u manager1 'http://127.0.0.1:8000/quotes/<ID>'
```

Ожидается `200 OK` и тот же черновик. Данные сохраняются в томе PostgreSQL. Команда `docker compose down -v` удаляет этот том.

## Тесты

Версии зависимостей закреплены в `constraints.txt`.

После сборки образа:

```bash
docker compose run --rm --no-deps api python -m pytest -q -p no:cacheprovider
```

Тесты проверяют создание и чтение черновика, сохранение при повторной инициализации, проверку входа, ограничения ролей, отказ в доступе к чужому объекту, закрепление организации и валидацию полей.

Для тестов используется отдельная временная SQLite-база. Демонстрационная PostgreSQL не затрагивается. Сохранение данных в PostgreSQL проверяется командами из раздела «Проверка API».

Для запуска тестов вне Docker нужен Python 3.12:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

## Ограничения

- HTTP Basic используется для локального запуска. Порт API опубликован только на `127.0.0.1`. Для удаленного доступа нужны HTTPS и пересмотр способа аутентификации.
- `/health` и `/docs` доступны без входа. `/health` проверяет соединение с БД.
- Таблицы создаются через SQLAlchemy `create_all`. Автоматического обновления структуры существующих таблиц нет.
- Создание учебных записей при запуске рассчитано на один экземпляр приложения.
