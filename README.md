# Quote Approval Service

Минимальная основа проекта для EK1: Python 3.12, FastAPI и PostgreSQL.

Сейчас менеджер может создать пустой черновик для закрепленной за ним организации и прочитать его по ID. Черновик сохраняется в базе и остается после перезапуска. Вход проверяется через HTTP Basic, пароли хранятся в виде хешей Argon2. Другой менеджер не видит чужой черновик; руководитель и клиент не имеют доступа к черновикам.

Позиции каталога, расчет цены, редактирование, фиксация версий, согласование, отправка и решения клиента пока не реализованы. Это первый технический результат, а не выполнение всех SR.

## Запуск

Нужны Git и запущенный Docker Desktop с Docker Compose. Отдельно устанавливать Python и PostgreSQL для этого способа не нужно.

Из папки репозитория:

```bash
cp .env.example .env
```

В `.env` замените обе заглушки на свои локальные пароли. Для `DEMO_PASSWORD` используйте не менее 12 символов. Файл `.env` не добавляется в Git.

```bash
docker compose up --build -d
docker compose logs api
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ проверки:

```json
{"status":"ok"}
```

Документация API: http://127.0.0.1:8000/docs. Кнопка **Authorize** принимает имя пользователя и пароль из `DEMO_PASSWORD`.

При первом запуске создаются таблицы и учебные записи:

| Пользователь | Роль | Доступ |
| --- | --- | --- |
| `manager1` | Менеджер | Организация 1 — Demo Client A |
| `manager2` | Менеджер | Организация 2 — Demo Client B |
| `lead` | Руководитель | Нет доступа к черновикам |
| `client` | Представитель клиента | Нет доступа к черновикам |

Для локальной демонстрации у всех четырех записей один пароль из `DEMO_PASSWORD`. Повторный запуск не удаляет записи и не меняет существующие пароли. Изменение `DEMO_PASSWORD` после первого запуска само по себе не обновляет пароли в базе.

## Проверка перед защитой

Создайте черновик. `curl` запросит пароль `manager1`:

```bash
curl -i -u manager1 -H 'Content-Type: application/json' \
  -d '{"client_org_id":1,"comment":"First draft"}' \
  http://127.0.0.1:8000/quotes
```

Ожидается `201 Created`, статус `draft`, `owner_id: 1` и новый `id`. Скопируйте ID из ответа вместо `<ID>`:

```bash
curl -i -u manager1 'http://127.0.0.1:8000/quotes/<ID>'
```

Ожидается `200 OK` и тот же черновик.

Проверьте ограничения:

```bash
curl -i 'http://127.0.0.1:8000/quotes/<ID>'
curl -i -u manager2 'http://127.0.0.1:8000/quotes/<ID>'
curl -i -u lead 'http://127.0.0.1:8000/quotes/<ID>'
```

Ожидаются соответственно `401`, `404`, `403`. Ответы не содержат условий черновика. Создание для незакрепленной или несуществующей организации возвращает `404`. Дополнительные поля вроде `owner_id`, `role`, `status` и `total` отклоняются с `422`.

Проверьте сохранение после остановки и повторного запуска:

```bash
docker compose down
docker compose up -d
curl -u manager1 'http://127.0.0.1:8000/quotes/<ID>'
```

Дождитесь готовности API; при необходимости посмотрите `docker compose logs api`. Данные хранятся в томе PostgreSQL. Не добавляйте `-v` к `down`, если хотите их сохранить.

## Тесты

Проверенные версии зависимостей закреплены в `constraints.txt`.

После сборки образа:

```bash
docker compose run --rm --no-deps api python -m pytest -q
```

Тесты проверяют создание и чтение, сохранение при повторной инициализации, отсутствие входа, неверный пароль, чужую роль, чужой объект, незакрепленного клиента и запрещенные поля. Они используют отдельную временную SQLite-базу и не меняют демонстрационную PostgreSQL. Проверка сохранения в PostgreSQL выполняется командами выше; тесты на SQLite не заменяют ее.

Для разработки вне Docker нужен Python 3.12:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

## Ограничения основы

- HTTP Basic выбран для локального запуска. API опубликован только на `127.0.0.1`; для удаленного доступа понадобится HTTPS и отдельное рассмотрение аутентификации.
- `/health` и `/docs` доступны без входа. Проверка `/health` подтверждает соединение с БД, но не выполнение всех функций проекта.
- Таблицы пока создаются через SQLAlchemy `create_all`. Это не система миграций: изменение структуры существующих таблиц потребует отдельного решения.
- Автоматическое создание учебных записей рассчитано на один экземпляр приложения.
