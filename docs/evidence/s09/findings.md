## F-01 — SQL при создании и удалении тестовой схемы

- **Правило:** `python.sqlalchemy.security.audit.avoid-sqlalchemy-text.avoid-sqlalchemy-text`.
  Severity анализатора — `ERROR`. [Исходный отчёт](initial/semgrep.json),
  [повторный отчёт](repeat/semgrep.json). Две строки относятся к одной причине.
- **Риск сигнала:** SQL-инъекция при интерполяции внешнего значения в `text()`.
- **Место:** [генерация имени, строка 24](https://github.com/evelonk/quote-approval-service/blob/e41e9b6774ba4adb66964460f56be155d664abcb/tests/conftest.py#L24),
  [CREATE, строка 26](https://github.com/evelonk/quote-approval-service/blob/e41e9b6774ba4adb66964460f56be155d664abcb/tests/conftest.py#L26),
  [DROP, строка 38](https://github.com/evelonk/quote-approval-service/blob/e41e9b6774ba4adb66964460f56be155d664abcb/tests/conftest.py#L38).
  Оба запуска проверяют один и тот же файл из e41e9b6.
- **Достижимость:** операции выполняет fixture `core_db` при pytest с PostgreSQL.
  Имя создаётся исключительно как `"test_" + uuid4().hex`: фиксированный префикс
  и 32 шестнадцатеричных символа. Кавычки и SQL-разделители попасть в имя не могут.
  HTTP-входов и подстановки имени из переменных среды нет. `CORE_TEST_DATABASE_URL`
  выбирает подключение к БД, но не формирует интерполируемое имя схемы.
- **Обоснование:** Semgrep обнаружил подстановку строки в SQL. Имя схемы полностью генерируется программой, не содержит внешнего ввода и не может включать символы, изменяющие структуру запроса. Поэтому для данной реализации сигнал SQL-инъекции признан ложноположительным.
- **Приоритет и действие:** исправление уязвимости не требуется; код сохранён,
  `nosemgrep` и исключения правил не добавлены. Повторная проверка даёт те же два
  сигнала, что соответствует разбору. Негативный тест «до/после исправления»
  неприменим: подтверждённой причины и исправления нет.
